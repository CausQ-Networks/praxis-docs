Praxis CLI is the recommended way to run a client using a command line interface on Mac and Linux.

Praxis CLI can run on Windows, but the CLI VPN functionality is not supported. With [companion mode](#companion-mode), connect in the Windows app and use the CLI for commands such as SSH, on the same account, without a second login.

Praxis CLI supports running as a user device with authentication or a machine client.

The CLI stores its own defaults in a config file.

Refer to the [documentation in the official repository](https://github.com/CausQ-Networks/praxis-cli/blob/main/docs/praxis.md) for the available commands, default values, and more.

## Install

Use this command to automatically install Praxis CLI. It detects your system architecture automatically and always pulls the latest version, adding `pangolin` to your PATH:

```bash
curl -fsSL https://praxis.causq.com/get-cli.sh | bash
```

On Windows, [download the latest installer](https://github.com/CausQ-Networks/praxis-cli/releases/latest/download/praxis-cli_windows_installer.msi), or choose to install the CLI from menu bar of the desktop app by choosing the "Install Praxis CLI" option.

Binaries for all platforms are available in the [GitHub releases](https://github.com/CausQ-Networks/praxis-cli/releases) for ARM and AMD64 (x86_64) architectures.

### Installation Steps

1. **Download and install the Praxis client**

   Install Praxis using the installation script:

   ```bash
   curl -fsSL https://praxis.causq.com/get-cli.sh | bash
   ```

2. **Log in with your Praxis account**

   Log in on your Praxis Cloud account or your self-hosted Praxis instance:

   ```bash
   praxis login
   ```

3. **Start Praxis**

   When logged in as a Praxis user, connect by running:

   ```bash
   praxis up
   ```

   To launch a machine client without logging in, use your client credentials:

   ```bash
   praxis up --id {client_id} --secret {client_secret} --endpoint {endpoint_url} --attach
   ```

   <Tip>
   The `--attach` flag runs the client in the foreground instead of spawning it as a background process.
   </Tip>

### Machine Clients

Machine clients don't require a login and are built for machines like services to be able to connect to private resources. Like sites, they have an ID and a secret.

#### Run as a Service

The CLI can install and manage a service on your host machine for you. This supports Windows services, MacOS's launchd, and Linux's systemd to create a persistent site connection from that host. 

```bash
sudo praxis service install client \
--id 31frd0uzbjvp721 \
--secret h51mmlknrvrwv8s4r1i210azhumt6isgbpyavxodibx1k2d6 \
--endpoint https://app.praxis.causq.com
```

Check the service status:

```bash
sudo praxis service status client
```

And to get the logs: 

```bash
sudo praxis service logs client
```

#### Systemd Service (Praxis CLI)

Create a basic systemd service for Praxis CLI:

```ini title="/etc/systemd/system/praxis-cli.service"
[Unit]
Description=Praxis CLI
After=network.target

[Service]
ExecStart=/usr/local/bin/praxis up --id {client_id} --secret {client_secret} --endpoint {endpoint_url} --attach
Restart=always
User=root

[Install]
WantedBy=multi-user.target
```

<Warning>
Make sure to move the binary to `/usr/local/bin/praxis` before creating the service. Replace `{client_id}`, `{client_secret}`, and `{endpoint_url}` with your machine client credentials and endpoint.
</Warning>

#### Docker (Praxis CLI)

You can run Praxis CLI with Docker Compose. For example, a service in your `docker-compose.yml` might look like this using environment variables (recommended):

```yaml
services:
  praxis-cli:
    image: causq-networks/praxis-cli:latest
    container_name: praxis-cli
    restart: unless-stopped
    network_mode: host
    cap_add:
      - NET_ADMIN
    devices:
      - /dev/net/tun:/dev/net/tun
    environment:
      - PRAXIS_ENDPOINT=https://app.praxis.causq.com
      - CLIENT_ID=5n52gnzfgl3tdox
      - CLIENT_SECRET=wyael1dhftekp0ii2ni0ym6xczwjnwmucy2vr6u9kgkp8tw9
```

You can also pass the CLI args to the container:

```yaml
services:
  praxis-cli:
    image: causq-networks/praxis-cli:latest
    container_name: praxis-cli
    restart: unless-stopped
    network_mode: host
    cap_add:
      - NET_ADMIN
    devices:
      - /dev/net/tun:/dev/net/tun
    command:
      - up
      - --id
      - "5n52gnzfgl3tdox"
      - --secret
      - "wyael1dhftekp0ii2ni0ym6xczwjnwmucy2vr6u9kgkp8tw9"
      - --endpoint
      - https://app.praxis.causq.com
      - --attach
```

**Docker Configuration Notes:**

- `network_mode: host` brings the Praxis CLI network interface to the host system, allowing the WireGuard tunnel to function properly
- `cap_add: - NET_ADMIN` is required to grant the container permission to manage network interfaces
- `devices: - /dev/net/tun:/dev/net/tun` is required to give the container access to the TUN device for creating WireGuard interfaces

<Note>
Deploying in Kubernetes? See [Kubernetes Deployment](/manage/clients/kubernetes/deployment) for a basic guide, including how to run the client as a sidecar container.
</Note>

## Companion Mode

Companion mode lets Praxis CLI use the [Windows desktop app](/manage/clients/platforms/windows#companion-mode) for authentication and the tunnel. Log in and connect in the desktop app, then run CLI commands as that same account. You do not run `praxis login` separately.

Companion mode is available on Windows only, and it requires Praxis for Windows 0.11.0 or later. On macOS and Linux the CLI keeps its own login, and `praxis companion` is not available. On Windows, companion mode is on by default.

### SSH through the desktop connection

1. Log in and connect with the Windows client.
2. SSH to a [private SSH resource](/manage/resources/private/ssh):

```bash
pangolin ssh username@alias
```

The CLI uses the desktop app's session and the tunnel that app already opened. `praxis scp` works the same way.

### Commands

Enable companion mode. This takes effect on the next `pangolin` command:

```bash
pangolin companion enable
```

Turn it off and go back to a standalone CLI login:

```bash
pangolin companion disable
```

Check whether the desktop app session is ready:

```bash
pangolin companion status
```

When the desktop app is logged in, status looks like this:

```text
Companion mode: enabled
Client: Praxis Windows
Ready: yes
```

If the desktop app is not logged in, status reports `Ready: no` and tells you to open Praxis and log in.

With companion mode off, status reports:

```text
Companion mode: disabled
Auth source: standalone CLI
```

### What stays in the desktop app

While companion mode is on, the CLI reads accounts, the active organization, and exit node selection from the desktop app. Change those in the app.

These commands are blocked. The CLI tells you to use the desktop app, or to run `praxis companion disable`:

- `praxis login`
- `praxis logout`
- `praxis select account`
- `praxis select org`
- `praxis select exit-node`

Other commands, including `praxis ssh` and `praxis scp`, run with the desktop app's session. The desktop app has to be open and logged in. If it is not, the CLI asks you to start Praxis for Windows 0.11.0 or later and log in.

You can also set `disable_companion_mode` in the [CLI config file](#config-file). `true` matches `praxis companion disable`.

## Configure

<Note>
DNS, MTU, and other connection settings are the same on every platform and are on [Platforms](/manage/clients/platforms#connection-settings).
</Note>

### Config File

The Praxis CLI stores persistent settings in `~/.config/praxis/config.json` on every platform. When the CLI is run with `sudo`, it uses the home directory of the user who invoked `sudo`, so the same file applies with and without it. Run `praxis config path` to print the exact location.

<ResponseField name="Config" type="object">
  JSON configuration for the Praxis CLI stored in `config.json`.

  <Expandable title="Config">
    <ResponseField name="log_level" type="string">
      Controls CLI log verbosity. Supported values are `debug` and `info`. If omitted, the default is `info`.
    </ResponseField>

    <ResponseField name="log_file" type="string">
      Path of the client log file. If omitted, the default is `~/.config/praxis/logs/client.log`. This key can only be changed by editing the file; it is not available through `praxis config set`.
    </ResponseField>

    <ResponseField name="disable_update_check" type="boolean">
      When true, the CLI does not check for new versions. If omitted, the default is `false`, except in builds distributed through a package manager, where it is `true`.
    </ResponseField>

    <ResponseField name="disable_companion_mode" type="boolean">
      When true, the CLI uses its own standalone authentication instead of [companion mode](#companion-mode), where login, accounts, organizations, and exit node selection are managed by the Praxis desktop app. If omitted, the default is `false`, so companion mode is on. This only applies on Windows.
    </ResponseField>

    <ResponseField name="companion_app_data_dirs" type="object">
      Overrides where the CLI looks for the desktop app's data directory in companion mode. Accepts a `windows` and a `darwin` path. Most installations should leave this unset. This key can only be changed by editing the file.
    </ResponseField>

    <ResponseField name="session_cookie_name" type="string">
      Overrides the cookie name used for the CLI's session token. Most deployments should leave this unset.
    </ResponseField>

    <ResponseField name="up.override_dns" type="boolean">
      Default for `--override-dns`. When true, matches the [Enable Aliases (Override DNS)](/manage/clients/platforms#enable-aliases-override-dns) setting and lets the client take over DNS resolution for Praxis resources. If omitted, the default is `true`.
    </ResponseField>

    <ResponseField name="up.tunnel_dns" type="boolean">
      Default for `--tunnel-dns`. When true, matches the [DNS Over Tunnel](/manage/clients/platforms#dns-over-tunnel) setting and sends DNS queries through the Praxis tunnel. If omitted, the default is `false`.
    </ResponseField>

    <ResponseField name="up.upstream_dns" type="array of strings">
      Default for `--upstream-dns`. Upstream DNS servers used when override/tunnel DNS is enabled. With `praxis config set`, pass a comma-separated list such as `10.0.0.53,10.0.0.54`.
    </ResponseField>

    <ResponseField name="up.match_domains_dns" type="array of strings">
      Default for `--match-domains`. Optional whitelist of domains sent to the configured upstream DNS server. When unset, all queries go to upstream DNS. When set, only matching queries use your Upstream DNS Server; all other requests use the system's DNS servers. Supports wildcards such as `*.proxy.internal`. With `praxis config set`, pass a comma-separated list.
    </ResponseField>

    <ResponseField name="up.prefer_local_routes" type="boolean">
      Default for `--prefer-local-routes`. When true, prioritizes local routes over remote ones by adding an arbitrary metric to the WireGuard routes. This is useful when you want to ensure that local network traffic (for example, to a printer or NAS) is not routed through the Praxis tunnel. If omitted, the default is `false`.
    </ResponseField>

    <ResponseField name="up.exit_node_takes_precedence" type="boolean">
      Default for `--exit-node-takes-precedence`. When true, matches the [Exit Nodes Take Precedence Over Resources](/manage/clients/platforms#exit-nodes-take-precedence-over-resources) setting. While connected through an exit node, routes for other resources are not added and their aliases are not resolved, so all traffic flows through the exit node. If omitted, the default is `false`.
    </ResponseField>

  </Expandable>
</ResponseField>

## Update

Find the latest version in the [GitHub releases](https://github.com/CausQ-Networks/praxis-cli/releases).

### Automatic Updates

If you already have Praxis CLI installed, use the update command:

```bash
pangolin update
```

Or you can re-run the installation script:

```bash
curl -fsSL https://praxis.causq.com/get-cli.sh | bash
```

### Manual Updates

Download the latest binary for your system from [GitHub releases](https://github.com/CausQ-Networks/praxis-cli/releases) and replace your existing binary.

```bash
wget -O praxis "https://github.com/CausQ-Networks/praxis-cli/releases/download/{version}/praxis-cli_{architecture}" && chmod +x ./praxis
```

<Note>
Replace `{version}` with the desired version and `{architecture}` with your architecture. Check the [release notes](https://github.com/CausQ-Networks/praxis-cli/releases) for the latest information.
</Note>

## Uninstall

To stop CLI site or client services, remove the binary, and delete local config, see [Uninstall Praxis CLI](/manage/clients/platforms/uninstall-cli).
