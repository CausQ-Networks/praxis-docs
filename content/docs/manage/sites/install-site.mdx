The site connector can be installed as either a static binary executable or a Docker container via the CLI. You must first create a site and copy the ID and secret config from Praxis before running it.

<Note>
The Praxis CLI is the recommended way to install a new site. Existing Newt deployments keep working. For Newt-specific install commands, see [Install Newt](/manage/sites/install-newt).
</Note>

## Binary Installation (Linux, macOS, Windows)

### Install

Use this command to automatically install the CLI. It detects your system architecture automatically and always pulls the latest version, adding the CLI to your PATH:

```bash
curl -fsSL https://praxis.causq.com/get-cli.sh | bash
```

To run a site on Windows, [download the latest installer](https://github.com/CausQ-Networks/praxis-cli/releases/latest/download/praxis-cli_windows_installer.msi).

Binaries for Linux, macOS, and Windows are available in the [GitHub releases](https://github.com/CausQ-Networks/praxis-cli/releases/latest) for ARM and AMD64 (x86_64) architectures.

### Running the Site

Run the site connector with the configuration from Praxis:

```bash
praxis up site \
--id 31frd0uzbjvp721 \
--secret h51mmlknrvrwv8s4r1i210azhumt6isgbpyavxodibx1k2d6 \
--endpoint https://app.praxis.causq.com
```

### Run as a Service

The CLI can install and manage a service on your host machine for you. This supports Windows services, MacOS's launchd, and Linux's systemd to create a persistent site connection from that host. 

```bash
sudo praxis service install site \
--id 31frd0uzbjvp721 \
--secret h51mmlknrvrwv8s4r1i210azhumt6isgbpyavxodibx1k2d6 \
--endpoint https://app.praxis.causq.com
```

Check the service status:

```bash
sudo praxis service status site
```

And to get the logs: 

```bash
sudo praxis service logs site
```

### Manual Systemd Service

Create `/etc/praxis/praxis-site.env` with the initial values from your Praxis site configuration:

```bash title="/etc/praxis/praxis-site.env"
SITE_ID=31frd0uzbjvp721
SITE_SECRET=h51mmlknrvrwv8s4r1i210azhumt6isgbpyavxodibx1k2d6
PRAXIS_ENDPOINT=https://app.praxis.causq.com
```

Create the directory, write the file, and restrict its permissions:

```bash
sudo install -d -m 0755 /etc/praxis
sudo editor /etc/praxis/praxis-site.env
sudo chmod 600 /etc/praxis/praxis-site.env
```

Then create a systemd service. The site connector reads those environment variables automatically, so `ExecStart` does not need to repeat them as flags:

```ini title="/etc/systemd/system/praxis-site.service"
[Unit]
Description=Praxis Site
Wants=network-online.target
After=network-online.target

[Service]
Type=simple
User=root
Group=root
EnvironmentFile=/etc/praxis/praxis-site.env
ExecStart=/usr/local/bin/praxis up site
Restart=always
RestartSec=2
UMask=0077

PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

<Warning>
Make sure the binary exists at `/usr/local/bin/praxis` before daemon reload and starting the service: `~$ which praxis`
</Warning>

Reload systemd and enable the service:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now praxis-site
sudo systemctl status praxis-site
```

If you later change `/etc/praxis/praxis-site.env`, restart the service so the site connector picks up the new values.

See [Configure Sites](/manage/sites/configure-site) for more environment variables.

## Docker Installation

### Pull the Image

Pull the latest image from Docker Hub:

```bash
docker pull causq-networks/praxis-cli:latest
```

### Run with Docker

Run the site connector with CLI arguments from Praxis:

```bash
docker run -dit --network host causq-networks/praxis-cli up site --id 31frd0uzbjvp721 \
--secret h51mmlknrvrwv8s4r1i210azhumt6isgbpyavxodibx1k2d6 \
--endpoint https://app.praxis.causq.com
```

<Note>
Host networking lets the site see the host's real network addresses, which clients on the same LAN need for [same-network detection](/manage/clients/nat-traversal#same-network-detection). On a bridge network the site only sees the container's internal addresses and those clients connect through hole punching or the relay instead. Add `network_mode: host` to the Compose service on Linux if you want local connections.
</Note>

### Docker Compose

#### Environment Variables (Recommended)

```yaml title="docker-compose.yml"
services:
  praxis-site:
    image: causq-networks/praxis-cli
    container_name: praxis-site
    restart: unless-stopped
    environment:
      - PRAXIS_ENDPOINT=https://app.praxis.causq.com
      - SITE_ID=2ix2t8xk22ubpfy
      - SITE_SECRET=nnisrfsdfc7prqsp9ewo1dvtvci50j5uiqotez00dgap0ii2
```

#### Config File Injected as Compose Secret

A safer but slightly more complex way is to use [Compose Secrets](https://docs.docker.com/compose/how-tos/use-secrets/). First, create a `JSON` file containing your configuration:

```json title="praxis-site-config.secret"
{
  "id": "2ix2t8xk22ubpfy",
  "secret": "nnisrfsdfc7prqsp9ewo1dvtvci50j5uiqotez00dgap0ii2",
  "endpoint": "https://app.praxis.causq.com"
}
```

Then register and reference the secret in your `docker-compose.yml`:

```yaml title="docker-compose.yml"
services:
  praxis-site:
    image: causq-networks/praxis-cli
    container_name: praxis-site
    restart: unless-stopped
    command:
      - up
      - site
    environment:
      - CONFIG_FILE=/run/secrets/praxis-site-config
    secrets:
      - praxis-site-config

secrets:
  praxis-site-config:
    file: ./praxis-site-config.secret
```

This allows you to separate sensitive secrets from plain configuration, improving security when storing or sharing your `docker-compose.yml` anywhere else.

#### CLI Arguments

```yaml title="docker-compose.yml"
services:
  praxis-site:
    image: causq-networks/praxis-cli
    container_name: praxis-site
    restart: unless-stopped
    command:
      - up
      - site
      - --id 31frd0uzbjvp721
      - --secret h51mmlknrvrwv8s4r1i210azhumt6isgbpyavxodibx1k2d6
      - --endpoint https://app.praxis.causq.com
```

#### Docker Healthcheck

The site connector supports healthchecks as described in [Configure Sites](/manage/sites/configure-site#param-health-file). This file can be used to do a
healthcheck from within docker (compose file).

We need to define the `HEALTH_FILE` environment variable as well as the healthcheck itself:
```bash
    environment:
      - HEALTH_FILE=/tmp/healthy
    healthcheck:
      test: ["CMD-SHELL", "[ -f /tmp/healthy ]"]
      interval: 30s
      timeout: 5s
      start_period: 30s
      retries: 3
```

Start the service:

```bash
docker compose up -d
```

## Platform-Specific Installation

### Unraid

Praxis Site is available in the Unraid Community Applications store. This template runs the Praxis CLI (`causq-networks/praxis-cli`) and is the recommended way to install a site on Unraid. Use it instead of the Newt Community Applications listing for new sites.

Search for **Praxis Site** and install the listing from **CausQ's Repository**. That is the officially supported template.
